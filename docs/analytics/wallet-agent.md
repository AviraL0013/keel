# Wallet completion evidence and route wiring

Recorded 2026-10-11. Scope is public, read-only Monad mainnet evidence. This branch does not change HTTP routes, the indexer, protocol ABIs, mobile code, or CI.

## Evidence

- The pinned [Exchange event ABI](../../packages/analytics/src/exchange-events.ts) names `PositionOpened[V2]`, `PositionIncreased[V2]`, `PositionDecreased`, maker fills, and `TakerOrderFilled[V2]`. A taker fill gives price, lot, fee, and balance, but no account or market ID. The [vendored Perpl history reference](../vendor/perpl-api-docs/rest-endpoints.md) gives account IDs and market IDs in authenticated fills; its trading-history endpoints require signed API-key requests. Public wallet routes cannot use those endpoints without a wallet's enrolled read key.
- At finalized Monad block `112397495`, hash `0x43c5d09a75fffb4cfb36cad21a04246cbb842b619d57c0d3855bd40af673cc69`, a read-only 20-block Exchange query returned six taker fills. Transaction `0x811e1a7a4b8fd541299ff02376e4c73a4723f42214f6b603e8d07cd451092748` had maker position/fill logs `47/48` followed by taker open/fill logs `49/50`. The taker open lot and fill lot were both `193`; entry price was `829910` PNS; fee was `56862` AUSD micros. Historical `getAccountById(4581)` and `getAccountByAddr` roundtripped at that exact block and hash to `0xE9f67986FE82F7439D78d4fBce3E4F1b91ecc70f`. A separate reduction transaction `0xdf59cebd9a95b8fd4ab758754872cecba330af4f6d2db8e9af2f0d0f60c71d16` had position/fill logs `29/30` with a matching 21-lot decrease. These observations support a strict receipt pattern; they do not establish that every historical taker settlement uses it.
- `attributeTakerFills` accepts a complete successful receipt with a matching canonical block header. It attributes a taker only when the immediately preceding global log is a supported position event and the exact lot change equals the taker lot. Opens require entry price equality; opens and increases require fee equality. Multiple maker partial fills produce one taker settlement, not one taker fill per maker. Close and inversion events lack enough lot evidence for this rule and stay unresolved. Unsupported or malformed evidence never becomes a wallet trade.
- `walletTakerTrades` requests `historicalAccountOwner` separately for every attributed account ID at the receipt's block and hash. The owner resolver checks chain 143, finalized height, the historical hash, address/ID roundtrip, and both hashes again. Ownership at one block says nothing about another block. Archive-state errors stop attribution; no current or `AccountCreated` address is substituted.
- `settlementEvidence` exposes the signed **gross** `deltaPnlCNS + fundingCNS` from reduction, close, inversion, liquidation, and deleveraging events. The [vendored position type](../vendor/perpl-api-docs/types.md) distinguishes realized delta and funding from fees, including fee shares released on exits. Gross event PnL is not net wallet profit. Unwinding events do not carry the same delta/funding fields, so their PnL stays unavailable.
- A current or historical `getPositionV2` view supplies venue `pnlCNS` when mark validity is true. `profileAt` reads every account and listed position at one requested finalized block, checks its supplied hash, then rechecks that block and the finalized boundary. The current profile already keeps whole-wallet equity null when its bitmap contains positions absent from public context.

## Still unavailable

- Complete public wallet realized PnL, win rate, profit factor, and episode statistics. Deployment-to-head logs, every event owner's block proof, all settlements, and fees would have to reconcile. `PositionUnwound[V2]` still lacks a verified PnL formula. Existing performance routes must continue returning null totals on incomplete history.
- Taker closes and inversions as trade rows under the current strict lot rule. These can be shown only after a separate size proof, such as a complete transaction-level position reconstruction.
- Liquidation price. The venue's full maintenance, funding, insurance, and fee threshold formula has not been independently verified. An observed liquidation execution price is not a live threshold.
- Full equity curve and maximum drawdown. Historical finalized snapshots are possible at selected blocks, but sparse snapshots cannot prove intervening peaks or troughs. The vendored trading history requires authentication and is outside the public wallet contract. Keep `equityCurve: []` and `maxDrawdownPct: null` in public performance responses.

## Exact HTTP integration steps

The following work belongs in `server/src/interfaces/http/routes/analytics.ts` and indexer/repository files. It is intentionally not included in this branch.

1. At `/wallets/:address/trades`, retain the existing maker extraction but remove the static `analytics_accounts` ownership join as a wallet attribution claim. For each maker candidate, use its indexed block number/hash and `wallet.ownerAt(accountId, block, hash)`; include it only when that exact proof's address equals the requested address. Any missing proof makes the page partial. Preserve the current one-position-event-per-maker-fill rule and null realized PnL for ambiguous transactions.
2. For taker candidates, query `analytics_raw_events` for `TakerOrderFilled` and `TakerOrderFilledV2` up to the same checkpoint block. Fetch each candidate's **complete** `eth_getTransactionReceipt`; check chain ID 143, receipt success, transaction hash, finalized height, canonical block number/hash/time, and a second canonical hash read after all calls. Stop on HTTP 401/403. Adapt every receipt log to `ChainLog` hex fields and pass all logs, including other contracts, to `attributeTakerFills`. Build its precision map keyed by Exchange `perpetual_id`, with `marketId` set to the API market `id`.
3. Pass each attributed taker fill through `walletTakerTrades(address, fills, wallet.ownerAt.bind(wallet))`. Do not cache ownership by account ID alone: only `(accountId, block, blockHash)` may share a proof. If a proof call fails, fail that response or mark its range unresolved; never use a present-day owner as fallback.
4. Merge verified maker and taker `VerifiedHistoryTrade` rows. Provide a complete candidate set for the requested range before calling `pageVerifiedWalletTrades(rows, limit, cursor)`. The helper uses the route's existing `(block, transactionIndex, logIndex)` cursor. Overlap duplicates collapse only when identical; conflicting duplicates fail. Keep the response `stale: true` and history partial while any taker, settlement, owner, market, or archive evidence is unresolved. A page of visible rows is not a complete wallet total.
5. At `/wallets/:address/performance` and `/wallets/compare`, add `e.block_number`, `e.transaction_hash`, `e.log_index`, and `e.size_raw` to the episode query. Pass `eventId` and liquidation `remainingSizeRaw` to `calculateWalletPerformance`. The repository already writes remaining size for liquidation events and classifies nonzero remainders as reductions. Full liquidations without an explicit zero remainder now fail closed. Before publishing non-null metrics, verify complete deployment-to-checkpoint coverage, exact owner proofs at every event block, all taker and maker settlements, and supported unwind treatment. Continue returning the existing null performance object until those gates hold.
6. For a bounded historical equity sample, call `wallet.profileAt(address, context, blockNumber, canonicalHash)`. Only display its non-null `margin.equity` with block/hash provenance. Do not fill missing blocks, extend an owner proof across blocks, derive liquidation price, or calculate a complete equity curve or drawdown from sparse samples.

Focused tests: `tests/analytics-wallet-history-taker.test.ts`, `tests/analytics-wallet-history-pagination.test.ts`, `tests/analytics-owner-proof.test.ts`, `tests/analytics-wallet-snapshot.test.ts`, and `tests/analytics-performance.test.ts`. Receipt tests use canonical ABI encoding of observed event shapes; they are offline regressions, not a full historical replay.
